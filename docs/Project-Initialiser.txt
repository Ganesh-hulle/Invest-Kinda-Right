# Algo Trader Project Context & Requirements

## Project Overview

I am building a **production-quality personal algorithmic trading platform** primarily for learning and portfolio purposes. The goal is not just to create an algo trading application, but to build a software system using real-world software engineering practices similar to those used in fintech companies.

The application will eventually connect to my existing Zerodha trading account using Kite Connect APIs and allow both paper trading and live intraday algorithmic trading.

The project should be designed as if it will eventually be used in production.

---

# Primary Objectives

The application should eventually support:

* User authentication
* Live market data streaming
* Technical indicator calculation
* Multiple trading strategies
* Paper trading
* Live trading through Zerodha
* Risk management
* Trade journal
* Performance analytics
* Mobile dashboard
* Backtesting engine

The focus is equally on learning software architecture and cloud deployment, not just trading.

# Development Philosophy

The application should resemble a production system.

Code should follow:

* SOLID Principles
* Clean Architecture where appropriate
* Thin Controllers
* Business Logic inside Services
* DTOs
* Repository Pattern
* Constructor Injection
* Global Exception Handling
* Structured Logging
* Validation
* Flyway Migrations

Avoid overengineering.

Do not introduce unnecessary frameworks or abstractions.

---

# Development Workflow

I **will not** start by deploying to AWS.

Development will happen in stages.

---

## Stage 1

Local Development

Run:

Spring Boot from IntelliJ

Flutter from Android Studio / VS Code

PostgreSQL inside Docker

Redis inside Docker

Reason:

Running Spring Boot directly from IntelliJ provides much faster development and debugging than rebuilding Docker images after every code change.

---

## Stage 2

Local Docker Testing

Once features are complete:

Create Dockerfile.

Create docker-compose.yml.

Run the complete backend stack locally.

Services:

* Backend
* PostgreSQL
* Redis

This ensures production parity before deployment.

---

## Stage 3

AWS Deployment

Deploy Docker containers onto AWS EC2.

The AWS environment should closely resemble the local Docker environment.

Eventually introduce:

* Nginx
* HTTPS
* Domain
* GitHub Actions deployment pipeline
